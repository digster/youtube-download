# 2026-11-19

## Archive checks before playlist downloads

- Custom creation and YouTube video-list fetches queue Finder checks in the
  membership transaction. Explicit video and metadata refreshes request fresh
  results. Downloads wait for the initial scan, and manual selection remains
  independent of every Finder result. Existing lists acquire missing checks
  before their next download or through a refresh.
- SQLite shares results and pending requests by video ID across playlists.
  The single Finder worker and manual lookups share a persistent cooldown.
  Each request, including redirect hops, waits at least five seconds after the
  preceding response. HTTP 429/503 honor Retry-After with a sixty-second
  fallback. Failed refreshes retain previous links. Opening results uses local
  data. Ordinary library polling sends link counts, with full links for the
  video under review.
- The library's Archive links filter and row actions expose source, destination,
  content flags and notes for each link. YouTube originals and partial results
  are labeled separately. An individual recheck enters the same queue.
- Verified with 236 passing tests, desktop and mobile Chromium, and an isolated
  live Shelf server with two mock Finder requests 5.008 seconds apart. One
  request to the public service for the public video jNQXAC9IVRw returned 11
  links. Tested shared IDs, metadata refresh, missing legacy checks, retained
  results, manual checkbox edits during a scan, redirects and restart backoff.
  The full suite has the existing Starlette/httpx deprecation warning.
