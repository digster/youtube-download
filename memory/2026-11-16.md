# 2026-11-16 — Initial playlist downloader and folder relocation

## Implemented

- Started from an empty directory. Inspected both sibling projects' README,
  architecture, instructions, and recent memory.
- Selected youtube-backup for reusable read-only OAuth/private account access;
  youtube-client's API-key access does not enumerate private account playlists.
- Created a uv-managed Python 3.12 project using FastAPI, SQLite, yt-dlp,
  youtube-backup as a sibling path dependency, and a buildless HTML interface.
- Added account playlist sync, lazy item sync, batch selection, durable jobs,
  pause/resume, subprocess termination, restart recovery, stable video paths,
  after_move receipts, and a per-video runner lock/parent-death watchdog.
- Added individual playlist library pages, file validation, playback with byte
  ranges, missing/unavailable states, archive links, and metadata retention.
- Integrated youtubevideofinder's published v5 API with a seven-day cache,
  normalized metadata/video URLs, bounded network requests, and error retention.
- Added per-playlist folder reassignment: existing absolute directories, relative
  recorded file paths, moved receipt reconciliation, file rechecking, and blocks
  while a process is active. The app does not move files itself.
- Added setup guidance, dotenv examples, rotating logging, localhost protections,
  documentation, an empty AGENTS.md, prompt history, learnings, and MIT license.

## Decisions and limits

- macOS/Linux local application; no cloud deployment or multiuser mode.
- API-owned playlists plus Liked videos; Watch Later and saved playlists from
  other owners are not exposed by this API integration.
- Archive links can be metadata only and are never automatically downloaded.
- Explicit refresh fetches playlist additions; retry uses the cached snapshot.
- The user's explicit request authorizes commits in this task. Use digster with
  the provided GitHub noreply email; no assistant coauthor. No push requested.
