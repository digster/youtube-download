## Adaptive library and sign-in polling

- The user reported continuous local API hits and approved frequent active-job
  polling, slower idle checks, and immediate refresh on returning to a tab.
  Commit authorization remains active; use digster's GitHub noreply identity
  without assistant attribution. No push requested.
- Added buildless `static/polling.js`, loaded before app.js. Independent
  completion-scheduled timers refresh the library every 2 seconds for queued/
  running downloads or metadata jobs, otherwise every 30 seconds. Failures use
  a 30-second retry interval even with stale active state. Slow reads never
  overlap. Immediate post-action refreshes coalesce into a trailing read when
  an older GET is still in flight, preserving prompt progress after mutations.
- Hidden/page-hidden tabs suspend timers; returning or restoring from the page
  cache refreshes immediately. Duplicate restore events are handled once.
  In-flight reads may finish while hidden but do not schedule more polling.
  Initial page loads still fetch their snapshot, including background loads.
- Sign-in has its own timer: 2 seconds while waiting/exchanging, 30 seconds in
  idle setup, stopped when setup is closed with no pending attempt. It never
  forces library polling. A revision counter rejects stale status reads after
  start/cancel/client-upload actions. Cookie/file drafts remain untouched.
- Wrote a failing idle-request regression first: the original frontend made
  15 requests in the first 30 seconds instead of one. Also reproduced stale
  sign-in response overwrites and duplicate page-cache/visibility refreshes
